## 4. สูตรคำนวณ (CR ข้อ 13 – 21)

คิดที่ระดับกรมธรรม์/สลักหลังรายบรรทัด ปัดทศนิยม 2 ตำแหน่ง แล้วจึงรวมเป็นกลุ่ม

| รายการ | สูตร |
| --- | --- |
| ค่าใช้จ่าย 1 | `ROUND(เบี้ยสุทธิ × MIN(%ค่าใช้จ่าย, 18%), 2)` |
| ค่าใช้จ่าย 2 | `ROUND(เบี้ยสุทธิ × MAX(%ค่าใช้จ่าย − 18%, 0), 2)` |
| ค่าใช้พิมพ์กรมธรรม์ | `ROUND(เบี้ยสุทธิ × 1%, 2)` เฉพาะกรมธรรม์ที่ตัวแทนพิมพ์เอง (`Y` / `1` / `Y/1`) |
| VAT 7% | `ROUND(ค่าใช้จ่ายแต่ละก้อน × 7%, 2)` — เฉพาะนายหน้า/ตัวแทนที่จดทะเบียน VAT |
| TAX 3% | `ROUND(ค่าใช้จ่ายแต่ละก้อน × 3%, 2)` — เฉพาะนายหน้า/ตัวแทนที่จดทะเบียน VAT |
| ยอดชำระทั้งสิ้น | `TOTAL AMOUNT DEBIT − DD − OP − TS − BC − AC − TO OTHER − Tax Deduct` |

## 6. ข้อจำกัดและสิ่งที่ต้องยืนยัน

1. **ชื่อตาราง/คอลัมน์บางส่วนยังไม่ได้ตรวจกับ Data Dictionary จริง** — ดู
   [`docs/SCHEMA-CHECKLIST.md`](docs/SCHEMA-CHECKLIST.md) ทุกจุดถูกทำเครื่องหมาย `[SCHEMA BINDING]` ในสคริปต์
2. **การพิมพ์ PDF** — PowerBuilder 8.0 ไม่มี `SaveAs(PDF!)` (เริ่มมีใน PB 10)
   หน้าจอจึงสั่งพิมพ์ผ่านไดรเวอร์เครื่องพิมพ์ PDF โดยกำหนด `Print.FileName` ต่อ 1 ใบนำส่งฯ
   เครื่องผู้ใช้ต้องตั้งเครื่องพิมพ์ PDF เป็น Default Printer
3. **รูปแบบ Excel** — ใช้ `Excel5!` ซึ่งเป็นรูปแบบสูงสุดที่ PowerBuilder 8.0 รองรับ
   (`Excel8!` เริ่มมีใน PB 10)
4. **การแบ่งค่าใช้จ่าย 1 / ค่าใช้จ่าย 2 ในกลุ่มอัตราเกิน 18% ยังไม่ยุติ (OI-06)** — ข้อความใน CR
   ขัดแย้งกับตัวเลขตัวอย่างในไฟล์เงื่อนไข สคริปต์ยึดตามข้อความใน CR (ค่าใช้จ่าย 1 = ส่วนที่ไม่เกิน 18%)
   หากฝ่ายธุรกิจยืนยันว่าตัวอย่างถูก ให้สลับนิพจน์ `exp1` / `exp2` ใน `sql/03_*` — **กระทบยอดเงินโดยตรง**
5. **คอลัมน์ "เบี้ยประกันภัย ปัดเศษทศนิยม"** — ยังสรุปสูตรจากตัวอย่างเดียวในไฟล์เงื่อนไขไม่ได้
   จึงดึงจากฟิลด์ที่จัดเก็บไว้ (`round_adj`) แทนการคำนวณซ้ำ — เป็นข้อ **OI-01** ที่ต้องยืนยัน

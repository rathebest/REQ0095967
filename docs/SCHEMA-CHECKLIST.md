# รายการที่ต้องยืนยันกับ DBA ก่อนติดตั้ง — REQ0095968

เอกสาร CR REQ0095968 ระบุ **ความหมายทางธุรกิจ** ของทุกช่องไว้ครบถ้วน แต่ไม่ได้ระบุ
**ชื่อตาราง/คอลัมน์จริง** ในฐานข้อมูล ชื่อที่ใช้ในสคริปต์ `sql/03_*` และ `sql/04_*`
จึงอ้างอิงจาก 2 แหล่งเท่านั้น:

* DataWindow ของหน้าจอเดิม `d_acvun7122` (W_ACVUN711) ที่แนบมากับ CR
* Stored Procedure `proc_clrao102_dp_automatching` ที่ใช้โครงสร้างคีย์เดียวกัน

**ยังไม่ได้ตรวจสอบกับ Data Dictionary จริง** ทุกจุดถูกทำเครื่องหมาย `[SCHEMA BINDING]`
ไว้ในสคริปต์ กรุณาไล่ตรวจตามตารางด้านล่างก่อนรัน

---

## A. ยืนยันแล้ว — พบใน `d_acvun7122.srd` ที่แนบมากับ CR

ใช้ได้เลย ไม่ต้องแก้

| ตาราง | คอลัมน์ |
| --- | --- |
| `dbo.debit_list` | `flag_debit_type`, `debit_no`, `debit_no_belongto`, `br_code`, `debit_undtype`, `receipt_date`, `operator_login`, `sale_code`, `total_amount_debit`, `total_amount_deposit`, `total_amount_ac`, `total_amount_br_income_expense`, `total_amount_return`, `amt_return_to_salemgr`, `amt_return_to_cmi` |
| `dbo.sale` | `sale_code`, `fname`, `lname`, `code` |
| `dbo.prename` | `code`, `prename_desc` |
| `dbo.debit_detail` | `br_code`, `debit_no`, `debit_undtype`, `flag_debit_type`, `flag_receipt_type` |

เงื่อนไขการกรองที่ยืนยันแล้วเช่นกัน: `debit_undtype = 'V'` (ภาคสมัครใจ) และ
`flag_debit_type = 'C'` (ใบนำส่งประเภทตัดชำระเบี้ย)

รูปแบบเลขที่ใบนำส่งฯ ยืนยันจากนิพจน์ใน `d_acvun7122`:

```
'V' + debit_no_belongto + flag_debit_type + right(debit_no,5) + '/' + left(debit_no,2)
```

→ `debit_no` เป็น `CHAR(7)` = `YYNNNNN` แสดงผลเป็น `NNNNN/YY` เช่น `6800025` → `VAC 00025/68`

```

```

ถ้าในตารางมีคอลัมน์ที่เก็บยอดนี้ไว้แล้ว (เช่น `debitnote_total_net`) ควรใช้ค่าที่เก็บไว้แทนการคำนวณซ้ำ
